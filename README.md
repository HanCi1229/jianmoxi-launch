**为散文、文学小说与诗歌写作者设计的 AI 阅读与写作空间。**

## 为什么做笺墨溪

很多写作从一段记忆、一个画面或读过的一句话开始。读的时候有感受，过几天想写却找不到原文，也记不起当时为什么被打动。即使素材还在，面对空白页，作者仍要想清楚从哪个细节起笔。草稿写出来之后，又需要一个可以讨论措辞、视角和节奏的对象。

笺墨溪把这些散在书库、摘录、聊天和文档里的工作接到一起。作者可以从阅读或灵感开始，把原文片段或自己的草稿带进对话，让 AI 搭子「小溪」陪着细读、追问和讨论，再回到文章继续写。作品保留作者自己的叙述视角与修改选择。

## 四个空间怎样接起来

| 空间 | 解决的具体问题 | 产品设计 |
| --- | --- | --- |
| **阅读** | 一句话离开上下文后，容易忘记它出自哪篇、原文在说什么。 | 按作品、作者或正文检索，回到完整作品阅读，选段可摘录或带进对话。 |
| **灵感** | 收藏了很多句子，真正开始写时难以找到和此刻主题相关的素材。 | 按主题发现有出处的文字，保留摘句和来源，允许收藏或直接带入写作。 |
| **对话** | 写作者有感受却说不清，也很难用一句通用提示解释正在写的稿子。 | 把选中的原文或当前文章作为对话对象，由小溪围绕具体文字发问、解读和讨论修改。 |
| **文章** | 草稿需要反复续写和修订，作者也需要留存自己的成稿。 | 组织标题和正文，支持草稿继续编辑、云端保存、完成标记与导出。 |

## 一个具体的 AI 产品决定

当作者请小溪从指定作品中制作灵感卡，模型负责理解主题、筛选候选摘句和撰写解读。系统核对摘句是否出现在检索到的原文里，作者、作品和章节由书库记录填写。保存时再复核原文，确保卡片能回到出处。

把摘录与解读分别处理，是因为它们有两种不同的质量要求。解读允许开放的文学判断，引用必须经得起逐字回查。对作者来说，这张卡才有可能在另一次写作中继续使用。

## 产品定位

[阅文作家助手](https://www.yuewen.com/app/?type=appzj) 面向网络文学创作，服务持续写作、作品管理与发布。笺墨溪面向传统文学创作者，重点是从细读、素材积累到起笔与反复修订。两类产品服务不同的创作节奏，也有不同的验收重点。笺墨溪关注素材能否回查、对话能否围绕具体文字，以及作者能否把讨论接回自己的稿子。
